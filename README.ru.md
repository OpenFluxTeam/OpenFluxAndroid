## Что это

[OpenFlux](https://github.com/OpenFluxTeam/OpenFlux) — инструмент исследования сетевого стека: туннель IPv4 TCP/UDP с подключаемыми транспортами (включая подписанный JS-движок для написания новых), пакетный кодек с zstd и два бэкенда выходной ноды (L3 — прямая пересылка пакетов, L4 — прокси на gVisor).

OpenFluxAndroid — его клиент для Android. Ядро собрано в APK через мост gomobile (`mobile/`) и работает внутри VPN-сервиса приложения; приложение ведёт профили, транспорты, ключи и выходные ноды.

```
приложения ──> TUN VpnService  или  SOCKS5 ──> ядро OpenFlux ──> сессия транспортов ──> выходная нода ──> Интернет
                                               (в APK)           приоритеты, переключение  --mode l4 | l3
```

## Возможности

### Туннель

- **Системный VPN** через `VpnService` Android: весь трафик устройства идёт в туннель; собственный трафик приложения в него не попадает.
- **Режим прокси**: локальный SOCKS5 для приложений, которые вы на него направите.
- **IPv4 TCP и UDP**; через ноду L3 — IP-пакеты целиком, включая ICMP.
- **Плитка в быстрых настройках** — подключиться и отключиться, не открывая приложение.

### Транспорты и сессии

- **Встроенные транспорты** ядра: Яндекс Документы, Яндекс Volga, Яндекс Доска, Mail.ru, cups.online, Телемост, Avito, MAX/OneMe и `direct` — обычное TCP-соединение с вашей нодой.
- **JS-транспорты**: подписанные пакеты для скриптового движка ядра, ставятся из комплекта, с GitHub или по ссылке. Ядро проверяет подпись каждого пакета; приложение показывает его параметры и отправляет пакет на ваши ноды.
- **Сессии из нескольких транспортов**: в профиле несколько транспортов, у каждого приоритет и сети, где ему можно работать (мобильная сеть, Wi-Fi). Согласование аутентифицировано; если активный канал встал, сессия переходит на следующий, не разрывая туннель.
- **Сначала прямое подключение**: пока `direct` до ноды жив, трафик идёт по нему раньше документов — с MTU туннеля 16000 байт, пулом буферов и Reno на его потоках.
- **Группы полос**: несколько каналов одного или разных типов работают как одна полоса, по дорожке на канал.
- **Кодек** на профиль: пакетный с zstd или прежний LZ4 по пакету для старых нод.

### Шифрование

- **AES-256-GCM сквозь** — от телефона до выходной ноды, ключ на канал. С ключом сервис, который несёт документы, видит только шифротекст.
- Ключи нод создаёт мастер; они передаются внутри ссылки на профиль и никуда больше не уходят.

### Выходные ноды

- **Мастер ноды по SSH** прямо с телефона: ставит выходную ноду ядра на сервер (Linux amd64, arm64, armv7) и задаёт ей бэкенд и транспорты:
  - **L4** — TCP/IP-стек gVisor в пространстве пользователя: завершает соединения и открывает новые; root не нужен, работает везде;
  - **L3** — пересылка IP-пакетов как есть через SNAT/DNAT, одно соединение из конца в конец; нужны root и iptables.
- **Проверка**: после установки приложение подключается через новую ноду и проверяет, что адрес выхода — адрес сервера.
- **Каналы сервера**: список, смена транспортов (ключ, порт и контекст сохраняются), поделиться, удалить, добавить.
- **Совсем без сервера**: выходом может быть небольшая программа на PHP на обычном веб-хостинге.
- **Ноды обновляются сами**: нода скачивает новые релизы, сверяет их с `SHA256SUMS` и откатывается, если новая сборка не запустилась.
- **Этот телефон как выход**: через него могут подключаться другие устройства.

### Ещё

- **Ссылки `openflux://` и QR-коды** несут профиль целиком: транспорты, приоритеты, ключ, кодек; камера считывает их обратно.
- **Встроенный браузер** (WebView) для проверок, которые просят некоторые сервисы, например SmartCaptcha или стена входа.
- **Журнал ядра** с уровнями отладки, прямо в приложении.
- **Обновления** из релизов GitHub, со сверкой с `SHA256SUMS.txt` релиза, ставятся только с вашего согласия; APK подписаны одним ключом релизов.
- **Аккаунт openflux.dev** для подписок — по желанию; всё перечисленное работает и без него.

## Что нового в текущем релизе

Релиз **3.9** идёт с ядром OpenFlux 0.14.0 (выходная нода `node-v1.7.0`), встроенным в APK.

- **Сначала прямое подключение**: обычное TCP-соединение с нодой используется раньше документов, пока оно живо.
- **Скорость**: MTU туннеля 16000 байт на direct с откатом по ICMP «нужна фрагментация», пул буферов отправки, zstd только где он помогает (никогда поверх TLS на direct), Reno на прямых потоках.
- **Группы полос** в ядре вместо прежнего объединения каналов.
- **Перезапущенная нода подхватывается сразу**: перезапущенный выход отвечает клиенту посреди сессии.

Полный список — в [CHANGELOG.md](CHANGELOG.md).

## Установка

Скачайте APK на [странице релизов](../../releases/latest): универсальный или под ваш процессор (`arm64-v8a` для большинства телефонов, `armeabi-v7a` для старых, `x86` и `x86_64` для эмуляторов). Разрешите установку из браузера или файлового менеджера, которым вы скачали файл.

## Сборка из исходников

Нужны JDK 17, Go, Android SDK с NDK 27 и `gomobile` (`go install golang.org/x/mobile/cmd/gomobile@latest`).

```bash
git clone --recurse-submodules https://github.com/OpenFluxTeam/OpenFluxAndroid.git
cd OpenFluxAndroid
scripts/build-android-core.sh          # собирает androidApp/libs/openflux.aar из сабмодуля OpenFlux/
./gradlew :androidApp:assembleDebug    # APK, по одному на ABI
```

Клонировали без `--recurse-submodules`? Выполните `git submodule update --init --recursive`. `scripts/build-android-core.sh ../OpenFlux` собирает из отдельного клона вместо сабмодуля. Пересобирайте AAR после каждого изменения Go API ядра или сабмодуля `OpenFlux/`.

## Устройство

```
androidApp/   VPN-сервис и мост к ядру, плитка быстрых настроек, проверки в WebView, камера (QR)
shared/       Сабмодуль: модели, сессии, настройки транспортов, мастер ноды, экраны
OpenFlux/     Сабмодуль: ядро (CLI и мост mobile/ для gomobile)
scripts/      build-android-core.sh
```

Клиент для компьютера — [OpenFluxDesktop](https://github.com/OpenFluxTeam/OpenFluxDesktop); оба используют модуль [OpenFluxClientShared](https://github.com/OpenFluxTeam/OpenFluxClientShared).
